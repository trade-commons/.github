# Security Policy

## Reporting a vulnerability

Do not open a public issue for a security vulnerability.

Use GitHub's private vulnerability reporting on the affected repository, under its Security tab. If
that is unavailable, use the contact address published on <https://trade-commons.github.io>.

Include what you did, what happened, and what you expected, with enough detail to reproduce it. A
proof of concept is welcome and never required.

## What to expect

Acknowledgement within five working days. These are volunteer-maintained repositories under a
foundation that is still forming, so a precise remediation timetable cannot yet be promised.
Disclosure will be coordinated with you and credit given unless you prefer otherwise.

## Scope

This policy covers the code in this organisation. It does not cover a deployment operated by someone
else from that code, which is the operator's responsibility, nor the normative specifications, where
a defect goes to the governing standards body through its own process.

A vulnerability affecting a specification rather than an implementation should be reported to the body
that governs it. Reach the maintainers here if you are not sure which it is, and they will route it.
